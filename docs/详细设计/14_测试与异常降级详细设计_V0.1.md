# AE 内部知识平台 V1——测试与异常降级详细设计

版本：V0.1  
状态：讨论稿

日期：2026-08-24  
依赖：DD-04、DD-05、DD-06、DD-07、DD-08、DD-10、DD-15

## 1. 设计目标

本设计将 V1 的业务要求转换为可执行测试和异常处理规则，重点保证：

- 没有企业知识证据时不生成确定性产品事实；
- 外部模型、飞书、对象存储和检索引擎失败时有明确降级；
- 重试不会重复写入文档、回答、引用或任务结果；
- 文档新版本失败不破坏当前可查询版本；
- 答案、引用和状态转换满足原子性；
- RAG 质量可以通过真实黄金问题集重复评测。

## 3. 外部依赖异常策略

### 3.1 统一错误分类

```text
可重试临时错误
  ├── 连接超时
  ├── 429 限流
  ├── 502/503/504
  └── 外部服务短暂不可用

不可重试业务错误
  ├── Token 无权限
  ├── 文档不存在
  ├── 文件格式不支持
  ├── 模型返回 Schema 不合法
  └── 配置引用不存在
```

临时错误进入任务重试；业务错误直接失败并保存稳定 `error_code`。不能依据异常文本是否包含“timeout”来决定重试，必须由适配器返回结构化错误分类。

### 3.2 依赖矩阵

| 依赖 | 临时失败 | 业务失败 | 最终用户行为 |
|---|---|---|---|
| 飞书元数据/正文 | 有限重试 | 标记授权失效或资源不存在 | 文档进入失败/待重新授权，不入库 |
| 对象存储 | 有限重试 | 文件校验失败 | 任务失败，保留原因，可人工重试 |
| 文档解析器 | 不重试同一输入超过上限 | 记录格式/损坏原因 | 文档失败，不进入分类和索引 |
| 分类模型 | 有限重试 | Schema 无法修复则分类失败 | 进入待确认或失败，不进入查询 |
| Embedding | 有限重试 | 维度/Schema 错误直接失败 | 保留旧版本可查询，新版本不可切换 |
| Rerank | 有限重试 | 使用无 Rerank 降级 | 答案标记 `RERANK_FAILED` |
| 检索引擎 | 有限重试 | 返回查询不可用 | 不调用生成模型猜答案 |
| 答案模型 | 有限重试 | 输出无法校验则失败 | 不保存为成功答案，允许重试 |
| 飞书导出 | 有限重试 | 导出失败 | Markdown 导出仍可独立完成；显示飞书导出失败 |

## 4. RAG 异常与安全降级

### 4.1 检索降级规则

```text
BM25 + 向量 + Rerank
        ↓ 任一能力失败
BM25 + 向量
        ↓ 向量失败
BM25 only
        ↓ 检索引擎不可用
资料暂不可用，不调用答案模型
```

降级不改变事实边界：即使只剩 BM25，也必须有实际证据才能生成产品事实。

### 4.2 生成校验失败

模型输出必须通过：

1. JSON/Schema 解析；
2. block 类型和字段校验；
3. Citation ID 存在性校验；
4. 事实 block 引用完整性校验；
5. 数字、版本号和型号在证据中可定位校验；
6. 不允许输出任意外部 URL、SQL、工具调用或隐藏 Prompt。

首次失败可以进行一次结构化修复请求；修复仍失败则回答为 `FAILED`，不将原始自由文本作为正式答案展示。

### 4.3 文档正文提示注入

文档内容被视为不可信数据。解析、分类、检索和生成阶段都必须将正文与系统规则分隔。文档中的以下内容不能改变系统行为：

- 要求忽略系统指令；
- 要求调用接口或访问文件；
- 要求泄露 Prompt、Token 或其他文档；
- 要求把文档内容标记为最高优先级。

测试必须包含中英文混合、表格单元格、隐藏文本和 Markdown 指令等注入样本。

## 5. 文档流水线异常测试

| 场景 | 期望结果 |
|---|---|
| 同一飞书 token 重复提交 | 返回已有来源，不重复创建有效来源 |
| 本地文件 MD5 重复 | 标记重复，不重复解析/Embedding |
| 上传中断 | 暂存文件和任务可清理，不能产生 READY 版本 |
| 解析失败 | 保存错误原因，状态 FAILED，可重试 |
| 分类为 UNCERTAIN | 进入待确认，不进入检索 |
| 分类结果 Schema 错误 | 可修复一次，仍失败则任务失败 |
| 新版本处理失败 | 旧 READY 版本继续可查询 |
| 新版本成功但切换前来源下线 | 不自动恢复下线来源 |
| Worker 在最终切换前崩溃 | 重试不产生两个 current version |
| 用户重复撤回 | 幂等返回最终下线状态 |
| 非所有者撤回他人来源 | 返回业务错误，不改变状态 |

## 6. 问答测试设计

### 6.1 核心用例

| 编号 | 场景 | 期望结果 |
|---|---|---|
| TC-QA-001 | 产品规格直接查询 | 答案优先，引用实际规格文档 |
| TC-QA-002 | 产品信息只存在于旧版本 | 只使用当前 READY 版本 |
| TC-QA-003 | 知识库无产品参数 | 返回资料不足，不用模型记忆补齐 |
| TC-QA-004 | 有规格但无性能测试 | 回答配置，明确性能未确认 |
| TC-QA-005 | 同优先级来源冲突 | 默认采用更新时间较新者并提示确认 |
| TC-QA-006 | 产品、版本和文档类型筛选 | 实际过滤条件与页面展示一致 |
| TC-QA-007 | 多轮追问“它的内存呢” | 使用上下文解析，但重新检索当前知识 |
| TC-QA-008 | 信息不足 | 返回澄清问题，不生成确定结论 |
| TC-QA-009 | 总结多个来源 | 结构化输出并保留多个引用 |
| TC-QA-010 | 不支持版本对比的请求 | 明确提示 V1 暂不支持，不生成对比结论 |
| TC-QA-011 | Rerank 不可用 | 使用降级结果并展示降级提示 |
| TC-QA-012 | 检索服务不可用 | 不调用答案模型猜测 |
| TC-QA-013 | 文档包含提示注入 | 内容只作为证据，不改变系统行为 |
| TC-QA-014 | 同一会话并发发送两次 | 一次成功，另一次返回 409 |
| TC-QA-015 | SSE 断线后重连 | 返回 snapshot 和已持久化事件 |

### 6.2 引用评测

每个黄金问题至少评估：

- 检索是否召回正确来源；
- 关键答案点是否覆盖；
- 引用是否实际支撑答案；
- 引用链接和定位是否可用；
- 无依据问题是否拒答；
- 版本和来源优先级是否正确。

不能只使用模型自评。模型评估可以作为辅助，但关键问题仍需要人工标注或规则校验。

## 7. 质量指标

首轮不预设绝对上线阈值，先使用黄金问题集建立基线。至少记录：

| 指标 | 说明 |
|---|---|
| Recall@K | 正确来源是否进入候选集 |
| Evidence precision | 最终引用是否真正相关 |
| Key point coverage | 关键答案点覆盖比例 |
| Citation correctness | 引用是否支撑声明 |
| Citation completeness | 事实声明是否都有引用 |
| Abstention correctness | 无依据时是否正确拒答 |
| Helpful rate | 用户有帮助反馈比例 |
| No-result rate | 没有足够依据的问题比例 |
| First token latency | 首个答案块耗时 |
| End-to-end latency | 最终答案完成耗时 |

每次变更 Embedding、切片、来源优先级、Rerank、Prompt 或模型版本，都要使用同一问题集重跑并保留配置版本。

## 8. 测试数据原则

- 测试数据不使用真实密码、Token、OA 密码或客户敏感信息；
- 使用脱敏后的产品规格、版本功能和案件样本；
- 每个黄金问题绑定期望关键答案点和允许来源；
- 同一问题覆盖充分、部分、冲突、无依据和降级结果；
- 记录模型、Prompt、索引和配置版本，保证结果可重现。

## 9. V1 验收出口

满足以下条件后，才进入实现验收：

1. 关键业务状态均有正向和失败测试；
2. 文档新版本失败不会破坏旧版本查询；
3. 产品事实无引用时不会进入成功答案；
4. 外部模型超时、限流和非法输出均有稳定错误处理；
5. SSE 断线、重复提交和 Worker 重启有恢复测试；
6. 黄金问题集已建立，并完成首轮基线评测；
7. 所有 P0 页面至少有正常、空、加载、失败和重试状态；
8. 测试结果和未覆盖风险被记录，而不是只报告代码覆盖率。
