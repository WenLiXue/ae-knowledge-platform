## 1. 部署形态

采用容器化模块化单体：

```text
React 静态资源
       ↓
反向代理 / HTTPS
       ↓
FastAPI Web/API 进程
       ├── PostgreSQL
       ├── 对象存储
       ├── OpenSearch/Elasticsearch
       └── Worker / Scheduler
```

Web/API 和 Worker 使用同一代码版本、不同启动角色。V1 不拆微服务，不引入消息队列。

## 2. 运行进程

| 进程 | 职责 | 扩容方式 |
|---|---|---|
| Web/API | 登录、页面 API、提问、SSE | 按连接数扩容 |
| Worker | 文档治理、回答、导出任务 | 按任务积压扩容 |
| Scheduler | 每日 Wiki revision 检查和周期维护 | 单活实例或数据库租约 |
| Reaper | 回收过期租约和异常任务 | 可与 Worker 合并 |
| PostgreSQL | 业务事实、任务协调 | 公司数据库方案 |
| 检索引擎 | BM25、向量和过滤 | 公司搜索集群方案 |
| 对象存储 | 原文、快照、导出文件 | 公司对象存储优先 |

## 3. 配置与环境

环境变量只保存环境级配置和 secret reference，不保存业务配置正文。必须区分：

- 开发环境；
- 测试环境；
- 生产环境。

生产环境的数据库、对象存储、检索引擎和模型端点不得使用开发默认值。发布时记录应用版本、数据库迁移版本、模型配置 revision、Embedding revision 和索引 generation。

## 4. 监控指标

### 4.1 API

- 请求量、状态码和错误码；
- P50/P95/P99 延迟；
- SSE 活跃连接和断开数；
- 提问创建成功率；
- 409 并发冲突数量。

### 4.2 Worker

- 各 task_type 待处理数；
- 运行中、重试中和失败任务数；
- 任务耗时分布；
- 租约过期数；
- 重试次数和最终失败数。

### 4.3 RAG 与模型

- QueryPlan 生成失败；
- BM25/向量/Rerank 调用成功率；
- 召回候选数量和证据状态；
- 首 token 和最终回答耗时；
- 模型 Token 使用量；
- Citation 校验失败数；
- `INSUFFICIENT`、`PARTIAL` 和降级回答比例。

### 4.4 文档治理

- 飞书检查成功率；
- 解析、分类、Embedding、索引失败数；
- 当前 READY 文档数；
- 待确认分类数；
- 索引校验不一致数。

## 5. 告警

至少配置以下告警：

- PostgreSQL 不可连接；
- 检索引擎连续失败；
- 模型服务超时或错误率超过阈值；
- 任务积压超过阈值；
- 任务连续重试后失败；
- Wiki 每日检查未执行；
- READY 文档索引校验失败；
- 对象存储容量或写入失败；
- SSE 连接异常增长或持续断开。

告警必须包含服务、环境、时间、request_id/task_id 和处理建议，不在通知正文中携带敏感正文。

## 6. 备份策略

### 6.1 PostgreSQL

- 每日全量备份；
- 持续归档 WAL（若公司数据库平台支持）；
- 定期验证备份可恢复，而不是只验证文件存在；
- 会话、知识元数据、任务、配置和引用默认永久保留；
- 恢复前记录目标时间点和影响范围。

### 6.2 对象存储

备份范围包括：

- 原始文件或飞书版本快照；
- 解析产物；
- 导出文件（可按过期策略清理）；
- 必要的评测数据和配置快照。

原始文件与 Embedding 数据不是同一类备份对象。原始文件是恢复和重新解析的基础，向量/索引属于可重建派生数据，但索引 generation 元数据必须备份。

### 6.3 检索索引

- 业务事实以 PostgreSQL 为准；
- OpenSearch 索引可由 READY 版本重新生成；
- 生产环境可按容量和恢复目标执行快照；
- 重新建索引期间保留旧 generation，完成校验后再切换别名；
- 失败不得让查询切换到不完整 generation。

## 7. 恢复演练

至少验证：

1. PostgreSQL 从最近备份恢复；
2. 对象存储原始文件可读取；
3. 通过 READY 版本重建索引；
4. Worker 从租约过期任务恢复；
5. 外部模型临时不可用后任务可重试；
6. 恢复后历史回答引用仍能展示快照和失效状态。

## 8. 验收标准

| 编号 | 验收标准 |
|---|---|
| AC-OPS-001 | Web/API 与 Worker 可以独立重启和扩容 |
| AC-OPS-002 | Worker 崩溃后任务可通过租约回收恢复 |
| AC-OPS-003 | 关键 API、任务、RAG 和外部依赖都有基础指标 |
| AC-OPS-004 | 每日 Wiki 检查和失败重试可被监控发现 |
| AC-OPS-005 | PostgreSQL、原始文件和索引 generation 有明确备份策略 |
| AC-OPS-006 | 索引重建失败不影响当前可查询 generation |
| AC-OPS-007 | 至少完成一次恢复演练并记录结果 |
