# 产品知识智能平台 V1 需求基线

版本：V1.0  
阶段：需求分析完成稿  
范围：部门内部产品知识查询  
状态：待评审基线

## 1. 产品定位

面向部门内部用户建设产品知识查询系统。系统接入用户上传的文档和飞书 Wiki 文档，经过处理后提供以答案为主的知识查询，支持产品、版本和文档类型筛选、多轮追问、来源引用、会话持久化和用户反馈。

问题诊断是平台后续业务模块；CDT 日志分析是问题诊断下的一个用例，不纳入 V1 首期交付。

## 2. 业务目标

- 让 SEG、开发、测试等内部用户快速查询产品资料和历史经验。
- 统一接入产品规格、参数、版本功能、白皮书和 SEG 问题案件等知识。
- 让查询答案能够追溯到来源文档。
- 保存用户会话和必要的检索运行数据，支持后续运营分析和问题追踪。

## 3. 用户角色

| 角色 | V1 主要使用内容 |
|-|-|
| SEG 技术支持 | 产品资料、版本功能、参数、历史 SEG 问题案件 |
| 开发 | 产品设计、版本功能、参数、历史问题和修复资料 |
| 测试 | 产品功能、规格、测试相关资料和历史问题 |
| 项目经理 | 产品资料和版本功能 |
| 售前/售后 | 产品功能、规格、白皮书和部署资料 |
| PM/PMM | 产品功能、规格和白皮书 |
| 管理员 | 知识库维护、任务处理和运营统计 |

## 4. V1 业务范围

### 4.1 知识库

- 接入用户上传的文档。
- 接入已登记的飞书 Wiki 文档。
- 支持文档处理状态管理：处理中、成功、失败、下线、删除。
- 成功处理的文档进入查询范围。
- 失败任务记录失败原因并支持重试。
- Wiki 每日同步。
- Wiki 同步失败最多自动重试三次；三次失败后保留失败记录，管理员可手动重试。
- 文档更新后以最新版本为准，旧版本不参与正常查询。
- 文档下线后不参与正常查询。
- 文档删除后，历史对话仍保留当时的引用信息；用户点击失效链接时，应提示原文已删除或不可访问。
- 管理员负责知识库、文档状态和来源优先级维护。

### 4.2 产品知识查询

查询内容包括：

- 产品规格；
- 产品参数；
- 产品版本功能；
- 产品白皮书；
- SEG 问题案件；
- 历史类似问题；
- 所有已上传且成功处理的文档。

查询支持：

- 答案优先展示；
- 按产品、版本、文档类型筛选；
- 多轮追问；
- 新建会话；
- 用户停止继续询问；
- 用户删除或归档自己的会话；
- 会话导出或分享；
- 有帮助/没有帮助反馈；
- 无帮助原因选填；
- 多来源引用；

用户不能主动指定“只查某一种文档”，但可以使用产品、版本和文档类型筛选条件缩小结果范围。

## 5. 查询结果要求

### 5.1 统一展示结构

```text
综合答案
结构化信息（适用时）
适用范围、版本和限制
冲突提示（适用时）
来源文档列表
继续追问与反馈
```

查询页面以综合答案为主，不完整展开原文。来源区域展示文档名称、文档类型、版本或更新时间、章节/定位信息和原文链接，用户通过链接查看原文。

### 5.2 可组合展示原则

系统不要求用户预先选择知识类型，也不按文档类型套用固定答案模板。答案根据问题和证据组合以下展示块：

| 展示块 | 使用原则 |
|-|-|
| 综合文本 | 直接回答问题，概括有依据的关键结论 |
| 表格 | 规格、参数、版本对比、案件字段等结构化信息适用时使用 |
| 列表 | 多项能力、步骤、场景或限制适用时使用 |
| 适用范围 | 展示产品、版本、形态、前置条件和限制 |
| 冲突提示 | 展示冲突值、来源、更新时间和采用规则 |
| 来源 | 每项关键结论关联实际支撑它的文档和定位 |

例如 SEG 案件可以按问题只展示用户关心的字段，不要求每次完整输出全部候选字段。

### 5.3 SEG 问题案件字段

候选字段如下，最终字段仍需业务确认：

- 反馈日期；
- 案件描述；
- 客户；
- 类型；
- 优先级；
- 处理人；
- 状态；
- 问题原因；
- 解决办法；
- 问题分类；
- 关闭日期；
- 软件版本；
- 产品形态；
- 备注。

其中“类型”和“问题分类”的具体含义需要在后续评审中区分定义。

## 6. 内容冲突规则

### 6.1 同一文档的新旧版本

- 文档更新后，新版本覆盖旧版本。
- 正常查询只使用最新版本。
- 旧版本可以保留在历史记录中，但不作为默认查询依据。

### 6.2 不同来源、不同优先级

建议来源优先级为：

1. 正式产品规格/版本文档；
2. 正式测试结论；
3. 开发设计文档；
4. SEG 历史问题案件；
5. 一般说明或经验性资料。

系统优先采用高优先级来源，同时保留对用户判断有价值的限制和差异信息。

### 6.3 不同来源、同一优先级且内容冲突

- 默认以更新时间较新的来源作为主要依据；
- 答案中提示存在内容冲突；
- 展示参与冲突判断的来源和更新时间；
- 提示用户进行人工确认；
- 不得无提示地隐藏冲突来源。

### 6.4 依据不足

- 找到明确依据：直接回答并附来源；
- 找到部分匹配内容：说明适用范围和不确定性；
- 没有足够依据：明确提示资料不足，并可建议用户补充关键词、产品或版本信息；
- 不得将部分匹配内容包装成确定结论。

## 7. 会话、对话和反馈

- 系统持续保存用户对话记录到业务数据库。
- 对话记录包括问题、回答、多轮追问、来源、反馈、时间和状态。
- 用户可以查看自己的历史会话。
- 用户可以新建、删除和归档自己的会话。
- 用户切换话题时不强制新建会话。
- 用户可以导出或分享会话。
- 用户反馈包括“有帮助”和“没有帮助”；无帮助原因选填。
- 对话默认永久保存。

## 8. 数据保存与备份

默认持久化保存：

- 对话数据：默认永久保存；
- 查询及检索运行记录：默认永久保存；
- 账号信息：永久保存；
- 业务配置：永久保存；
- 知识文档元数据：默认长期保存；
- 原始文档及其处理记录：按业务保留策略保存。

备份需求：

- 业务数据库需要定期备份；
- 原始文档和上传日志需要独立备份；
- 备份数据需要加密并妥善保管；
- 应定期验证备份可恢复性；
- 备份失败应记录并告警；
- 具体备份频率、保留份数和恢复目标在概要设计阶段确定。

## 9. 管理和运营

管理员负责：

- 知识库维护；
- 文档状态维护；
- 来源优先级维护；
- 失败同步任务处理；
- 系统运行状态查看；
- 用户反馈分析；
- 查询量、无结果问题和低满意度问题统计；

运营统计至少包括：

- 查询次数；
- 活跃用户数；
- 会话数量；
- 无结果问题数量；
- 低满意度问题数量；
- 有帮助/无帮助比例；
- 高频问题；
- 文档处理成功率和失败率；
- Wiki 同步成功率和重试次数；
- 长期未更新文档数量。

## 10. 非功能需求原则

- 查询应尽可能快速，具体响应目标在设计和试点阶段确定；
- 单个文档、同步任务或查询失败不得影响其他用户和任务；
- 系统重启后，已持久化的对话、文档和任务记录应可恢复；
- 系统应支持根据实际用户规模评估并发容量；
- 系统应具备运行状态、失败任务和备份状态的可观察性。

## 11. V1 优先级

### Must Have

- 文档上传；
- 飞书 Wiki 每日同步；
- 文档处理状态；
- 同步失败记录、最多三次自动重试和管理员手动重试；
- 最新文档版本参与查询；
- 答案优先的产品知识查询；
- 产品、版本、文档类型筛选；
- 多来源和原文链接；
- 适合场景的结构化表格展示；
- 多轮追问；
- 会话持久化；
- 会话新建、删除和归档；
- 用户反馈；

### Should Have

- 会话导出和分享；
- 无依据/部分依据提示；
- 冲突来源提示；
- 管理员运营统计；
- 备份恢复验证机制。

### 后续版本

- 问题诊断模块；
- CDT 日志分析用例；
- 诊断报告生成和飞书云文档导出；
- 报告经用户同意后沉淀知识；
- 更复杂的报告协作和人工确认流程。

## 12. V1 验收标准

### 知识库

- 上传文档后显示处理状态。
- 成功处理的文档可被查询。
- 失败任务显示失败原因。
- Wiki 同步失败最多自动重试三次。
- 管理员可以手动重试失败任务。
- 文档更新后查询使用最新版本。
- 下线文档不出现在正常查询结果中。

### 产品知识查询

- 用户可以输入自然语言问题并获得答案优先的结果。
- 用户可以按产品、版本和文档类型筛选。
- 答案可以关联多个来源。
- 来源显示文档信息和原文链接。
- 结构化内容以表格展示。
- 同一优先级来源冲突时采用更新时间较新的内容，并提示人工确认。
- 依据不足时明确提示，不生成无依据确定结论。
- 用户可以多轮追问并查看会话记录。

### 会话

- 对话记录持久化保存。
- 用户可以查看、删除和归档自己的会话。

## 13. 后续设计与评审输入

以下细节在原型、详细设计和验收准备中继续确认，不改变 V1 业务边界：

1. SEG 案件字段最终定义和“类型/问题分类”的区别；
2. 不同问题场景下文本、表格、限制和来源等可组合展示块的交互细节；
3. V1 对话导出/分享的具体范围；
4. 数据库和原始文件的备份周期与恢复目标；
5. 基于已建立业务黄金问题集确定正式检索和回答验收阈值。
