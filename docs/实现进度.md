数据模型（对齐 DD-03，六张表）：

- `auth.users`：系统用户（登录未实现前，来源归属系统默认用户，见下文“实现决策”）。
- `knowledge.knowledge_sources`：来源聚合根，含 `uq_active_source_key` 部分唯一索引（`source_type, canonical_key WHERE status <> 'OFFLINE'`）。
- `knowledge.feishu_source_details`：飞书来源定位信息。
- `knowledge.document_versions`：文档版本，`UNIQUE(source_id, version_no)`。
- `tasking.processing_tasks`：处理任务，`uq_open_task_idempotency` 部分唯一索引（同一幂等键只允许一个未终结任务）。
- `tasking.task_attempts`：任务执行尝试。

业务能力：

- 提交幂等：同一飞书 token 只允许一个非下线来源；重复提交返回已有来源摘要（`duplicate=true`），不重复建源、不改变所有者；并发提交由数据库唯一约束兜底。
- 批量部分成功：单项独立事务，单项失败不影响其他已成功项；单次请求内重复 token 返回 `409 DUPLICATE_SUBMISSION`。
- 状态可追踪：来源 `PROCESSING/PENDING_CONFIRMATION/QUERYABLE/FAILED/OFFLINE`，版本与任务状态均落库。
- 失败可重试：`POST /api/v1/knowledge-sources/{source_id}/retry` 为失败来源创建新任务并通过 `parent_task_id` 关联旧任务，来源回到 `PROCESSING`；重试幂等（已存在未终结任务不重复创建）。
- API 路径保持不变，新增来源详情接口 `GET /api/v1/knowledge-sources/{source_id}`。
- 前端新增“已入库来源”区域，展示数据库真实状态（处理中/待确认/可查询/失败/已下线）。

### 第三阶段：任务 Worker 与 Mock 文档处理流水线（本阶段）

- 基于 `tasking.processing_tasks` 表的 Worker：`python -m app.worker` 独立进程轮询。
  - 领取：`FOR UPDATE SKIP LOCKED`，领取到期 PENDING/RETRY_WAIT，并回收租约过期的 RUNNING 任务。
  - 租约：领取时设置 `lease_owner`/`lease_expires_at`；`heartbeat()` 仅租约持有者可续租。
  - 重试：TRANSIENT 错误指数退避进入 RETRY_WAIT，耗尽（max_attempts）后 FAILED；VALIDATION/NOT_FOUND 立即 FAILED；来源下线 → CANCELED。
  - attempt：每次领取写入 `task_attempts`，完成回填结果；回收时旧 attempt 标记 ABANDONED。
  - 阶段链：成功创建下一阶段任务（幂等键 `version:{vid}:stage:{stage}`，`parent_task_id` 串联）。
- Mock 文档处理流水线（`app/worker/pipeline.py`）：FETCH → PARSE → CLASSIFY → CHUNK → EMBED → INDEX → FINALIZE。
  - 各阶段产物写入 `document_versions` 现有字段（raw/parsed 对象键、revision、解析器、embedding 模型/维度、index_generation）。
  - CLASSIFY 分支：RELEVANT 继续 / UNCERTAIN → `PENDING_CONFIRMATION` / IRRELEVANT → 来源 OFFLINE（明确无关）。
  - FINALIZE 激活事务：锁定来源、校验非 OFFLINE、切换 `current_version_id`、旧版本标 SUPERSEDED、来源 QUERYABLE。
  - 确定性测试注入（按来源 canonical_key 标记）：`fail-once`（首试失败重试成功）、`transient`（重试耗尽）、`permanent`（立即失败）、`uncertain`、`irrelevant`。
- 关键实现决策：任务 `scheduled_at` 显式用应用时钟写入（而非 DB `server_default`），避免 DB 与 Python 时钟漂移导致新任务被跳过。
- 测试：`tests/test_worker.py` 9 个用例覆盖正常推进、瞬时重试恢复、立即失败、重试耗尽、分类两分支、租约回收、失败后重试由 Worker 推进成功、心跳。全部套件 20 个测试稳定通过。

真实联调排障记录（已端到端验证通过）：

- **Bug 修复：app/tenant access token 解析**。飞书 `app_access_token/internal` / `tenant_access_token/internal` 把 token 放在响应**顶层**（`data` 之外），原先从 `data` 读取导致空 token → `Authorization: Bearer `（非法头）→ `FEISHU_NETWORK`。已改为顶层读取（`feishu_auth/real.py`、`feishu_provider/real.py`），并同步修正 MockTransport 测试响应。
- **跨站 Cookie 导致登录态 401**。回调在 `127.0.0.1:8000` 设置 `SameSite=Lax` 会话 Cookie，而前端页面在 `localhost:5173`，二者不同站，浏览器跨站 fetch 不携带 Cookie → `/auth/me` 401。已让 Vite 绑定 `127.0.0.1`、`FEISHU_FRONTEND_REDIRECT_URI=http://127.0.0.1:5173`，页面与 API 同站后 Cookie 生效。
- 前端嵌入式 QRLogin SDK 在部分环境 postMessage 不稳定（无消息到达 window），改为**直连跳转**：登录按钮直接跳转飞书授权页，绕开 tmp_code 环节。
- 验证：扫码 → 回调换 token → 绑定真实飞书身份（tenant_key + open_id）→ 建立会话 → 前端登录态生效。`/auth/me` 首次加载 401 属未登录探测的预期行为。
