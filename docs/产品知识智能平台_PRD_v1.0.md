# 产品知识智能平台 PRD

版本：V1.0 Draft  
状态：进行中  
范围：单一产品、部门内部试点

## 1. 项目概述

建设面向产品全生命周期的知识智能平台，统一沉淀研发、测试、部署、支持和产品资料，通过知识治理、混合检索、RAG 问答和故障诊断 Agent，提升知识查找、经验复用和问题定位效率。

平台包含两个核心业务能力：

1. 产品知识智能助手：回答产品功能、设计、测试、部署和历史经验问题。
2. 故障诊断智能助手：分析 CDT 日志和问题描述，关联历史知识，生成问题分析与定位报告。

## 2. 背景与问题

- 知识分散在飞书 Wiki、Word、PDF、Excel 和个人经验中。
- 文档分类、标签和质量不统一，检索成本高。
- 历史 Bug、修复记录和测试经验难以复用。
- CDT 日志分析依赖专家，问题定位周期长。
- 现有资料缺少结构化引用和可追溯的分析结论。

## 3. 产品目标

### 3.1 总目标

实现“知识可查询、经验可复用、问题可定位、结论可追溯”。

### 3.2 V1 目标

- 支持飞书 Wiki 文档同步和本地 Word/PDF/Excel 上传。
- 建立统一的文档解析、切分、标签和索引流程。
- 支持语义检索 + BM25 关键词检索 + 重排序。
- 支持带来源引用的自然语言问答和多轮追问。
- 支持 CDT 日志/问题描述上传、解析和诊断报告生成。
- 提供索引状态、解析失败和重试管理。

### 3.3 非目标

- V1 不自动修改生产环境配置或执行修复命令。
- V1 不替代人工审批和专家最终判断。
- 权限体系可先采用简化方案，正式上线前补齐企业级权限控制。

## 4. 用户角色与场景

|角色|核心场景|
|-|-|
|测试|查询测试方案、历史缺陷、验证方法|
|开发|查询设计、接口、代码说明、修复记录|
|项目经理|了解版本、功能、风险和交付信息|
|SEG 技术支持|快速分析客户问题和 CDT 日志|
|售前/售后|查询产品能力、部署和解决方案资料|
|PM/PMM|查询产品功能、规格和白皮书|

## 5. 产品架构

```text
用户
 ├─ 产品知识智能助手
 │   └─ Query 理解 → 知识域路由 → 混合检索 → Rerank → 答案与引用
 └─ 故障诊断智能助手
     └─ 日志解析 → 事件抽取 → 诊断规划 → 知识检索 → 证据校验 → 报告

知识来源：飞书 Wiki、Word、PDF、Excel、历史 Bug、测试记录、支持案例
```

## 6. 功能需求

### 6.1 知识接入

#### 飞书 Wiki

- 用户人工选择需要纳入的 Wiki 文档。
- 系统保存文档 token、标题、来源、版本和更新时间。
- 定时任务扫描已入库文档，发现更新后自动同步。
- 同步失败时记录错误原因并支持重试。

#### 文件上传

- 支持 Word、PDF、Excel。
- 上传后生成文档记录和处理任务。
- 文件原文保留，解析结果可追溯到原文件。
- 重复文件可根据文件指纹提示或跳过。

### 6.2 知识治理 Agent

对进入系统的文档执行：

- 文档解析和内容卫生检查。
- 自动识别产品、版本、模块、主题、关键词。
- 自动推荐一个或多个知识分类。
- 识别故障案例、修复记录、测试方案、部署说明等知识类型。
- 发现空文档、乱码、重复内容、异常表格和无法解析内容。
- 生成结构化元数据，供检索和过滤使用。

建议元数据：

```json
{
  "product": "产品名",
  "version": "版本号",
  "module": "模块名",
  "category": ["开发设计文档", "测试文档"],
  "knowledge_type": ["故障案例", "修复记录"],
  "source_type": "feishu_wiki",
  "source_url": "原文链接",
  "keywords": ["Analyzer", "Kafka"],
  "quality_status": "pending"
}
```

### 6.3 知识组织与索引

逻辑知识域建议包括：

- product：产品功能、部署、白皮书、规格。
- development：架构、接口、设计、代码说明、修复记录。
- testing：测试方案、测试报告、测试用例和验证结果。
- support：SEG 支持记录、FAQ、客户问题处理经验。
- incident：故障案例、问题分析和定位报告。

文档可同时属于多个知识域。存储实现可使用统一索引加 metadata 过滤，不要求每个逻辑知识域必须建立独立物理 collection。

### 6.4 知识检索与问答

- Query 理解：识别意图、产品、版本、模块、错误码和时间范围。
- 路由：根据问题类型选择一个或多个知识域。
- 召回：向量检索与 BM25 混合检索。
- 重排序：使用 reranker 对候选片段排序。
- 生成：基于证据生成答案，不足时明确说明信息不足。
- 引用：展示文档标题、章节、原文链接和相关片段。
- 多轮追问：保留会话上下文，支持用户补充版本、模块和日志信息。
- 防幻觉：答案中的关键结论必须能回溯到检索证据。

### 6.5 故障诊断 Agent

#### 输入

- CDT 日志文件或压缩包。
- 用户问题描述。
- 可选环境信息：产品版本、部署方式、模块、发生时间、变更记录。

#### 处理流程

1. 文件接收、格式识别和安全检查。
2. 日志解析：识别时间、级别、模块、线程、错误码、异常栈和关联 ID。
3. 事件归并：按时间、模块和调用链组织日志事件。
4. 问题抽取：提取现象、影响范围、首次异常和关键错误。
5. 诊断规划：决定需要查询的历史案例、开发资料、部署文档和测试记录。
6. 知识检索：调用 RAG 获取相关证据。
7. 假设生成与验证：区分直接证据、强关联线索和待确认假设。
8. 输出报告，并支持继续追问。

#### 报告结构

- 问题摘要。
- 影响范围。
- 日志关键时间线。
- 关键错误和异常链。
- 初步根因及证据。
- 可能原因排序。
- 建议排查步骤。
- 建议修复或缓解措施。
- 验证方案。
- 相关知识引用。
- 待补充信息和人工确认项。

诊断 Agent 只提供分析建议，不自动执行高风险修复操作；不确定结论必须标记置信度和证据缺口。

### 6.6 系统管理

- 查看文档总量、索引进度和最近同步记录。
- 查看解析失败清单、错误原因和重试入口。
- 查看知识治理结果和待人工确认项。
- 查看问答、诊断任务及报告状态。
- 查看操作审计：上传、删除、审核、同步和修改。

## 7. 业务规则与约束

- 原文是唯一事实来源，解析内容必须保留来源关联。
- 文档进入可检索状态前必须完成解析和基本质量检查。
- 自动分类是推荐结果，关键知识可要求人工确认。
- 同一文档允许多标签、多知识域归属，但不得复制多份原文。
- 诊断报告必须区分事实、推断和建议。
- 无足够证据时不得输出确定性根因。
- 删除或下线文档后，相关索引必须同步失效。
- 所有引用链接必须指向用户可访问的原文位置。

## 8. 权限与安全（后续阶段）

V1 可先采用内部统一访问；正式上线前支持飞书 SSO、角色映射、检索前过滤、引用过滤和审计日志。研发内部文档与对外向文档应在 metadata 层标记访问级别，避免仅依赖前端隐藏。

## 9. 非功能需求

- 可用性：单个文档处理失败不应阻塞其他文档。
- 可追溯：每个答案和诊断结论可追溯到原文、日志或推理步骤。
- 可观测：记录检索耗时、召回数量、重排序结果和模型响应状态。
- 可扩展：解析器、向量库、BM25、reranker 和模型可替换。
- 安全：上传文件隔离处理，限制文件类型、大小和压缩包层级。
- 数据保留：原文、解析结果、索引版本和报告版本可管理。

## 10. V1 验收标准

- 可成功接入飞书 Wiki 和 Word/PDF/Excel 文件。
- 可查看文档处理状态，失败任务可重试。
- 典型问题能够返回相关答案、来源和原文链接。
- 典型 CDT 日志能够生成结构化时间线和诊断报告。
- 报告能区分证据、推断和待确认项。
- 删除或更新文档后，检索结果在规定时间内完成同步。
- 关键操作和任务状态可查询。

## 11. 建议实施阶段

### 阶段一：知识库基础能力

接入、解析、切分、metadata、向量索引、BM25、基础问答和引用。

### 阶段二：知识治理与运营

自动分类、标签抽取、质量检查、同步更新、失败重试和管理后台。

### 阶段三：故障诊断 Agent

CDT 日志解析、事件抽取、诊断规划、历史案例关联和报告生成。

### 阶段四：企业化能力

飞书 SSO、角色权限、审计、指标体系和多产品扩展。

## 12. 待确认事项

1. 文档数量、单文件大小和每日更新量。
2. CDT 日志格式、压缩包结构和典型样本。
3. 知识库负责人及审核人选。
4. 内容卫生与相关性审核标准。
5. 是否允许多标签、多知识域和人工覆盖 Agent 分类。
6. 首批验收问题集、历史故障案例和评测标准。
7. 部署环境、模型/向量库选型和数据保留周期。
